# 饮食记录（DietTracker）

一个**离线优先**的 Android 应用：记录每天吃了什么（碳水 / 蛋白质 / 脂肪 / 热量），
同时管理健身训练（训练日、动作目标重量、成功失败记录）。

包名 `com.example.diettracker` · 应用名「饮食记录」 · minSdk 24（Android 7.0）·
targetSdk 34 · versionName 1.0 · 数据库版本 6

---

## 一、项目解决什么问题

日常健身的人有两件反复要做、又很难记清的事：

1. **今天到底吃了多少**——碳水、蛋白质、脂肪分别是多少，离目标还差多少；
2. **今天该练什么、用什么重量**——上次卧推练了多少、这次该不该加重量。

现有工具要么只做饮食、要么只做训练，要么必须联网、要么内置食物数据不全（外食、
包装食品、饮料查不到）。这个项目把两件事合并到一个不联网的应用里：

- 饮食侧：内置食物库（含麦当劳等品牌食品、常见主食蔬菜、泡面饮料啤酒咖啡），
  按每 100g 或按份记账，自动汇总碳蛋脂与热量，并按身体数据算出每日目标；
- 训练侧：把训练拆成**训练日**（如「胸 + 三头」），每个训练日有动作清单和
  「几天一次」的频率，到期的训练日自动出现在今日页；每个动作有**只属于这个训练日**
  的目标重量与步进，点「成功」就按步进加重，点「失败」重量不动；
- 全部数据存在手机本地（Room / SQLite），**不联网**、不需要账号。

## 二、主要功能

### 1. 今日页（默认首页）

| 区块 | 内容 |
|---|---|
| 当天摄入 | 碳水 / 蛋白质 / 脂肪 / 总热量四项进度条：未超标绿色、达到目标 90%-100% 黄色、超出红色；下方给出「饮食摄入 / 运动消耗 / 净热量」 |
| 今日训练 | 今天该练的训练日名称 + 该训练日下的动作卡片（动作名、目标组数 × 每组次数、目标重量）；每张卡片可标 **成功 / 失败 / 跳过**；训练日整体可 **跳过** 或 **延期** |
| 今日饮食 | 当天已记录的食物，按餐次分组，可编辑 / 删除 |

- 净热量 = 饮食摄入 − 运动消耗。**运动消耗只做显示参考，不会加回可摄入额度**
  （TDEE 已含活动系数，加回去等于双重计算）。
- 训练栏的加号：可以**添加整个训练日**，也可以**单独添加一个动作卡片**（不依赖任何训练日）。

### 2. 训练日的三种操作

| 操作 | 行为 |
|---|---|
| 动作卡片：成功 | 该动作**在本训练日内**的目标重量按步进值增加，下次用新重量；写入往期记录 |
| 动作卡片：失败 | 目标重量**不变**（永不自动降重）；写入往期记录 |
| 动作卡片：跳过 | 不写往期记录，目标重量不变 |
| 训练日：跳过 | 该训练日下所有动作自动标记「跳过」，从今天移除，不进往期 |
| 训练日：延期 | **所有训练日统一往后顺延一天**：今天的内容整体挪到明天，后续训练日一起顺延；不记成功失败 |

### 3. 库（训练动作 / 拉伸 / 食物）

- **训练动作库**：内置力量动作（含主要肌群、要点、关联拉伸）+ 用户自建动作；
- **拉伸库**：按目标肌群分组，每张卡片给出保持时间（20-30 秒）、组数（2-3 组）、
  做法与出处，并预留图片 / 视频位置（当前为空）；
- **食物库**：分「品牌食品」与「推荐食品」两栏，可搜索名称 / 品牌 / 标签。

### 4. 我的

| 入口 | 内容 |
|---|---|
| 每日目标 | 手工微调每日碳水 / 蛋白质 / 脂肪克数 |
| 训练日 | 创建 / 重命名 / 删除训练日；给训练日加动作；设置每个动作的目标组数、每组次数、目标重量、步进；设置「几天一次」频率；一键套用预设计划（三分化 / 五分化 / 六分化） |
| 往期训练记录 | 只显示标记为**成功 / 失败**的动作项目（跳过的永不出现），每条含日期、动作名、目标组数与次数、目标重量、结果 |
| 动作与拉伸库 | 跳到「库」页 |
| 身体数据 | 身高 / 体重 / 年龄 / 性别 / 体脂率（可选），活动系数，目标模式，以及估算结果 |

### 5. 营养与训练的计算

**BMR（Mifflin-St Jeor）**

- 男：`10 × 体重 + 6.25 × 身高 − 5 × 年龄 + 5`
- 女：`10 × 体重 + 6.25 × 身高 − 5 × 年龄 − 161`

**TDEE** = BMR × 活动系数（久坐 1.2 / 轻度 1.375 / 中度 1.55 / 高度 1.725）

**体脂率可选**：填了会额外用 Katch-McArdle（`370 + 21.6 × 去脂体重`）给一个**参考值**
并排显示，但**默认 TDEE 仍用 Mifflin 结果**。

**目标模式**

| 模式 | 热量 | 碳水 | 蛋白质 | 脂肪 |
|---|---|---|---|---|
| 增肌 | TDEE +15% | 45% | 30% | 25% |
| 保持 | TDEE | 50% | 25% | 25% |
| 减脂 | TDEE −20% | 35% | 40% | 25% |

按 碳水 4 kcal/g、蛋白 4 kcal/g、脂肪 9 kcal/g 换算成克数。

**训练消耗（MET）**：`消耗 = MET × 体重(kg) × 时长(小时)`，
大重量力量训练 MET 6.0 / 中等强度 MET 3.5；时长手填，估算值可被手动覆盖。

**训练日频率**：每个训练日设「几天一次」，到期就自动出现在今日页；
完成或跳过后，下次到期日 = 当天 + 间隔天数。

### 6. 内置食物数据

首次启动自动写入 **188 条**内置食物（品牌食品 160 条、通用/推荐 28 条）：

- 品牌：麦当劳（中国官网营养计算器，官方，单份计量含钠/钙）、肯德基、瑞幸、
  Manner、山姆；
- 包装食品与饮料：康师傅、统一、汤达人、农心、日清、今麦郎、双汇、同利德，
  以及可口可乐 / 百事 / 芬达 / 雪碧 / 冰峰 / 美汁源 / 维他 / 红牛 / 魔爪 / 佳得乐、
  青岛 / 雪花 / 燕京 / 百威 / 哈尔滨啤酒、星巴克咖啡等；
- 常见食物：大米、小米、面粉、黄豆、绿豆、番茄、青椒、菠菜、蛋糕、提拉米苏等。

每条都标注**来源**与**可信度**（官方 / 第三方 / 估算）。拿不到的数据一律记

## 三、安装方法

### 方式一：直接安装 APK（推荐自用）

1. 取仓库里的 `apk/diet-tracker-debug.apk`；
2. 传到 Android 手机（Android 7.0 及以上）；
3. 手机「设置 → 应用 → 特殊权限 → 安装未知应用」里允许对应来源安装，然后点击 APK 安装。

> 这是 **debug 签名**包，只适合自己用或测试，不能上架应用商店
> （上架需要 release 签名 + AAB）。

### 方式二：从源码构建

环境要求：

- JDK 17
- Android SDK（platform 34 + build-tools 34）
- 在项目根目录配置 `local.properties`：`sdk.dir=<你的 Android SDK 路径>`

命令：

```bash
# Windows
gradlew.bat :app:assembleDebug

# macOS / Linux
./gradlew :app:assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

其他常用命令：

```bash
gradlew.bat :app:testDebugUnitTest   # 跑单元测试（训练规则 / 频率排程）
gradlew.bat :app:kspDebugKotlin      # 只跑 Room 注解处理，导出 app/schemas/.../6.json
python tools/verify_migration.py     # 在真实 SQLite 上校验 v5 -> v6 迁移（先跑上面那条）
```

> **关于证书 / 代理**：仓库里的 `gradle.properties` **只放通用配置**（`-Xmx2048m
> -Dfile.encoding=UTF-8`），不含任何机器专有的证书路径或口令。如果你的网络环境有
> HTTPS 拦截（需要自定义信任库），**不要改这个文件**，用下面任一方式在本机注入：
>
> ```bash
> # 1) 命令行覆盖，只影响这一次构建
> gradlew.bat -Dorg.gradle.jvmargs="-Xmx2048m -Dfile.encoding=UTF-8 \
>     -Djavax.net.ssl.trustStore=<信任库路径> \
>     -Djavax.net.ssl.trustStorePassword=<口令> \
>     -Djavax.net.ssl.trustStoreType=PKCS12" :app:assembleDebug
>
> # 2) 写进本机的 ~/.gradle/gradle.properties（不会被提交）
> ```
>
> Gradle 分发与依赖仓库已配置为国内镜像（腾讯 / 阿里云）。

## 四、使用方法

### 第一次使用

1. 打开「**我的**」→ 填身高 / 体重 / 年龄 / 性别（体脂率可不填）→ 选活动系数与目标模式，
   下方立刻显示 BMR / TDEE / 目标热量与建议的碳水、蛋白质、脂肪克数；
2. 还在「我的」里点「**训练日**」→ 可以「新建训练日」，也可以直接**套用一个预设计划**
   （三分化 / 五分化 / 六分化，会生成整套训练日和动作）；
3. 进训练日里给每个动作设目标：目标组数、每组次数、目标重量、步进；设这个训练日的
   「几天一次」频率；
4. 回到「**今日**」页开始记录。

### 每天怎么用

- **记饮食**：今日页「今日饮食」右边加号 → 选食物 → 按克数或按份数填量 → 保存。
  顶部摄入卡片会实时变色（绿 / 黄 / 红）。
- **练训练**：今日页「今日训练」里，到期的训练日已经自动列出动作卡片；
  做到目标就点「成功」（目标重量按步进自动加重），没做到点「失败」（重量不变），
  没练这项点「跳过」。今天想加练就点训练栏的加号，加一个训练日或单独加一个动作。
- **记时长与消耗**：训练栏下方「时长/热量」→ 填时长、选强度，系统按 MET 估算消耗，
  也可以自己填；点「完成训练」后，消耗才会计入饮食页的「运动消耗」。
- **看历史**：我的 → 往期训练记录，只列成功和失败的动作（跳过的不会出现）。

### 几个行为约定（避免误会）

- 运动消耗**不会**加回可摄入额度，只做显示参考；
- 「失败」**永远不降重**，想降重请直接改目标重量；
- 步进值默认 **0 = 不自动加重**，要自动加重就得自己填一个步进；
- 「延期」是**全局**的：所有训练日一起往后顺延一天；
- 单独添加的动作卡片，目标重量就是添加时填的值，添加后没有修改入口（要改就删掉重加）。

## 五、输入输出示例

### 例 1：身体数据 → 每日目标

| 输入 | 值 |
|---|---|
| 身高 | 175 cm |
| 体重 | 70 kg |
| 年龄 | 25 |
| 性别 | 男 |
| 体脂率 | 不填 |
| 活动系数 | 中度 ×1.55 |
| 目标模式 | 保持 |

**输出**

```
基础代谢 BMR（Mifflin）  1674 kcal
每日总消耗 TDEE          2594 kcal
目标热量                 2594 kcal
建议每日目标：碳水 324 g / 蛋白质 162 g / 脂肪 72 g
```

（换算：碳水 2594×50%÷4 = 324g，蛋白质 2594×25%÷4 = 162g，脂肪 2594×25%÷9 = 72g）

若体脂率填 18.5%，会额外显示一行「BMR（Katch-McArdle 参考）」，但 TDEE 仍按上面算。

### 例 2：食物 → 营养与热量

输入：食物选「大米」，重量 100 g（该食物数据为每 100g）

输出（记入当天摄入）：

```
碳水 79 g · 蛋白质 7.5 g · 脂肪 0.5 g · 约 351 kcal
```

热量由碳蛋脂按 4/4/9 反算：`79×4 + 7.5×4 + 0.5×9 = 350.5 kcal`。

### 例 3：训练卡片标记 → 目标重量变化

设「胸 + 三头」里杠铃卧推的目标是 `4 组 × 8 次，目标 60 kg，步进 2.5 kg`：

| 操作 | 目标重量 | 往期记录 |
|---|---|---|
| 点「成功」 | 60 → **62.5 kg**（下次就用 62.5） | 新增一条：`2026-09-28 杠铃卧推 4 组 × 8 次 62.5kg 成功` |
| 点「失败」 | 60 → **60 kg**（不变） | 新增一条：`… 失败` |
| 点「跳过」 | 60 → **60 kg** | **不新增** |
| 整个训练日「跳过」 | 全部动作重量不变 | 该训练日不出现在往期 |

卡片上的显示形式是两段式：`本次 60kg → 下次 62.5kg`；步进为 0 时只显示
`本次 60kg`。

### 例 4：训练时长 → 运动消耗（MET）

| 输入 | 值 |
|---|---|
| 时长 | 60 分钟 |
| 强度档位 | 大重量力量训练（MET 6.0） |
| 体重 | 70 kg（取自身体数据） |

**输出**：`6.0 × 70 × 1 = 420 kcal`

这 420 kcal 会显示在今日页的「运动消耗」里，净热量 = 摄入 − 420；
**额度不会因此增加**。也可以手动改这个数字，改过之后标为「已手动填写」。

### 例 5：训练日频率 → 今日该练什么

| 输入 | 值 |
|---|---|
| 训练日 | 胸 + 三头 / 背 + 二头 / 腿 + 肩 |
| 频率 | 每 3 天一次 / 每 4 天一次 / 每 5 天一次 |

**输出**

```
今天：胸 + 三头（每 3 天一次，到期自动出现在今日训练栏）
点「成功」记完所有动作 → 下次到期日 = 今天 + 3 天
点「延期」             → 三个训练日的到期日全部 +1 天，今天不再显示
```

## 七、已知限制

1. **热量是碳蛋脂反算的**（4/4/9），食物表没有单独的「官方热量」列。因此少数条目
   反算值和来源对不上，备注里写了来源热量：牛油蛋糕（来源 420 / 反算 536）、
   芝士蛋糕（320 / 376）、出前一丁大盛杯面（445 / 缺碳水）、子母朱古力与 DHA+
   （70、57 / 缺蛋白）、青岛·雪花·哈尔滨啤酒（42、43、34 / 酒精热量不在碳蛋脂里）。
2. **饮料按每 100ml 录入**并写在备注里（应用内部按每 100g 存），星巴克因为官方只给
   「每份 Grande 473ml」，走按份计量存原始值、不做换算。
3. **完全离线**：没有账号、没有云同步；换手机需要自己迁移数据。
4. 拍照识别食物、AI 导入**尚未实现**。
5. 内置数据里标注为「第三方 / 估算」的条目仅供参考，请以包装标示为准。
