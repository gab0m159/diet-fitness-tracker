# 饮食健身记录（Diet & Fitness Tracker）

一个**完全离线**的 Android 应用：记录每天吃了什么（碳水 / 蛋白质 / 脂肪 / 热量），
记录每天练了什么（跑步、游泳、撸铁…），并按你的身体数据算出每日目标。

包名 `com.example.diettracker` · 应用名「饮食记录」 · minSdk 24（Android 7.0）·
targetSdk 34 · versionName 1.0 · 数据库版本 9 · 许可证 MPL 2.0

> **不联网、不需要账号、不上传任何数据。** 所有内容存在手机本地（Room / SQLite）。

---

## 一、项目解决什么问题

健身的人每天有两件事反复要做、又很难记清：

1. **今天到底吃了多少** —— 碳水、蛋白质、脂肪各多少，离目标还差多少；
2. **今天练了什么、消耗了多少** —— 跑了多久、举了多少，今天净摄入是多少。

现有工具要么只做饮食、要么只做训练，要么必须联网，要么内置食物数据不全（外食、
包装食品、饮料查不到）。这个项目把两件事合到一个**不联网**的应用里：

- **饮食侧**：内置 188 条食物数据（品牌餐品、包装食品、常见食材），按每 100g 或
  按份记账，自动汇总碳蛋脂与热量，并按身体数据算出每日目标；
- **运动侧**：内置 33 项运动（含撸铁），选项目 + 填时长就按 MET 算出消耗；
  撸铁还能往下挂动作卡片（动作 / 重量 / 组数 / 次数）；
- **净热量**：饮食摄入 − 运动消耗，一眼看清今天的账。

## 二、主要功能

### 1. 今日页（默认首页）

页面按 **当天摄入 → 今日饮食 → 今日运动** 排列。

**当天摄入**

| 内容 | 说明 |
|---|---|
| 三条进度条 | 碳水 / 蛋白质 / 脂肪。未超标显示各自颜色，达到目标 90%-100% 变**黄色**，超出变**红色** |
| 三个数字 | 饮食摄入 / 运动消耗 / 总热量（kcal） |

**今日饮食**：当天记录的食物，按餐次分组；右上角「+」添加。

**今日运动**：分上下两段 ——

| 段 | 内容 |
|---|---|
| 运动 | 跑步、游泳、骑行、跳绳…每项显示时长与消耗热量，可改时长、改热量、删除 |
| 撸铁 | 撸铁本身的时长与消耗 + 下面的动作卡片（动作名 / 重量 / 组数 / 次数） |

### 2. 运动热量怎么算

`消耗 ≈ MET × 体重(kg) × 时长(小时)`

- 每项运动的 MET 值内置（跑步 8.3、跳绳 12.3、撸铁 6.0…），取自通行的运动能量
  消耗对照表；
- 时长自己填（每项有默认值：有氧 30 分钟、拉伸 / 瑜伽 20 分钟、撸铁 60 分钟）；
- 算出来的热量**可以手动改成实测值**，改过会标「已手改」。

**运动消耗只做显示参考，不会加回可摄入额度** —— TDEE 已经含了活动系数，
再加回来等于双重计算。

### 3. 库

一级菜单两项：**运动** / **食物**。

**运动** 下面分三个二级菜单：

| 二级 | 内容 |
|---|---|
| 运动 | 33 项运动清单，按分组展示，每项显示默认时长、MET 值、按你体重估算的消耗 |
| 撸铁 | 动作库：内置动作（按部位分组）+ 自建动作，可搜索，自建动作可新建 / 编辑 / 删除 |
| 拉伸 | 按目标肌群分组的拉伸指导，含保持时间（20-30 秒）、组数（2-3 组）、做法与出处；预留图片 / 视频位置 |

**食物**：品牌食品 / 推荐食品分栏，可搜索名称、品牌、标签，可自建食物。

### 4. 我的

| 入口 | 内容 |
|---|---|
| 每日目标 | 手工微调每日碳水 / 蛋白质 / 脂肪克数 |
| 身体数据 | 身高 / 体重 / 年龄 / 性别 / 体脂率（可选） |
| 活动系数 | 久坐 ×1.2 / 轻度 ×1.375 / 中度 ×1.55 / 高度 ×1.725 |
| 目标模式 | 增肌 / 保持 / 减脂，选完立刻显示建议的每日克数 |
| 估算结果 | BMR、TDEE、目标热量与建议宏量 |

### 5. 营养与热量计算

**BMR（Mifflin-St Jeor）**

- 男：`10 × 体重 + 6.25 × 身高 − 5 × 年龄 + 5`
- 女：`10 × 体重 + 6.25 × 身高 − 5 × 年龄 − 161`

**TDEE** = BMR × 活动系数

**体脂率可选**：填了会额外用 Katch-McArdle（`370 + 21.6 × 去脂体重`）给一个**参考值**
并排显示，但**默认 TDEE 仍用 Mifflin 结果**。

**目标宏量：按体重直接给（不是按热量百分比切）**

| 模式 | 碳水 g/kg | 蛋白 g/kg | 脂肪 g/kg | 70kg 的人 |
|---|---|---|---|---|
| 增肌 | 4.0 | 1.8 | 1.0 | 280 / 126 / 70 g → 2240 kcal |
| 保持 | 3.5 | 1.6 | 0.9 | 245 / 112 / 63 g → 1995 kcal |
| 减脂 | 2.5 | 2.0 | 0.8 | 175 / 140 / 56 g → 1764 kcal |

**目标热量 = 碳水×4 + 蛋白×4 + 脂肪×9**，界面上只显示这一个热量数字；TDEE 只作参考。

> **蛋白质依据**：ISSN（国际运动营养学会）2017 年立场声明指出，增肌与维持肌肉
> **1.4–2.0 g/kg/天** 对多数运动人群已足够；热量缺口期为最大化保留瘦体重可能需要
> 2.3–3.1 g/kg。后者是针对**有训练经验的备赛运动员**的上限区间（且多按去脂体重
> 研究），对普通用户不现实，因此减脂期取 **2.0**——高于增肌（应对热量缺口），
> 但不进入那个区间。
>
> **脂肪依据**：取 0.8–1.0 g/kg。通行底线是 0.5–0.6 g/kg（维持激素水平），这里留得
> 更宽裕。碳水按训练强度给：增肌最高、减脂最低。

**目标模式**

三个模式的差别体现在「每公斤体重的克数」上（见上表），不再按热量百分比分配：

| 模式 | 定位 | 蛋白质 |
|---|---|---|
| 增肌 | 热量盈余、训练量大 → 碳水最高 | 1.8 g/kg |
| 保持 | 维持体重与训练表现 | 1.6 g/kg |
| 减脂 | 热量缺口 → 碳水最低、蛋白提高以保肌肉 | 2.0 g/kg |

按 碳水 4 kcal/g、蛋白 4 kcal/g、脂肪 9 kcal/g 换算成热量。

### 6. 内置食物数据

首次启动自动写入 **188 条**内置食物（品牌食品 160 条、通用/推荐 28 条）：

- **品牌餐品**：麦当劳（中国官网营养计算器，官方，单份计量含钠 / 钙）、肯德基、
  瑞幸、Manner、山姆；
- **包装食品与饮料**：康师傅、统一、汤达人、农心、日清、今麦郎、双汇、同利德，
  以及可口可乐 / 百事 / 芬达 / 雪碧 / 冰峰 / 美汁源 / 维他 / 红牛 / 魔爪 / 佳得乐、
  青岛 / 雪花 / 燕京 / 百威 / 哈尔滨啤酒、星巴克咖啡等；
- **常见食材**：大米、小米、面粉、黄豆、绿豆、番茄、青椒、菠菜、蛋糕、提拉米苏等。

每条都标注**来源**与**可信度**（官方 / 第三方 / 估算）。拿不到的数据一律记
「数据暂缺」，不编造；来源标注「微量（Trace）」的记 0 并在备注说明。

## 三、安装方法

### 方式一：直接安装 APK（推荐自用）

1. 从 [Releases](https://github.com/gab0m159/diet-fitness-tracker/releases) 下载
   `diet-fitness-tracker-v1.0.apk`（约 10 MB）；
2. 传到 Android 手机（Android 7.0 及以上）；
3. 手机上进入「设置 → 应用 → 特殊权限 → 安装未知应用」，允许对应来源安装，然后点击 APK。

> 这个包用**自签名证书**签名，适合自用与测试；上架应用商店需要另配 release 签名与 AAB。

### 方式二：从源码构建

环境要求：

- JDK 17
- Android SDK（platform 34 + build-tools 34）
- 在项目根目录配置 `local.properties`：`sdk.dir=<你的 Android SDK 路径>`

```bash
# Windows
gradlew.bat :app:assembleDebug

# macOS / Linux
./gradlew :app:assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

其他常用命令：

```bash
gradlew.bat :app:testDebugUnitTest   # 单元测试（运动热量 / 运动库 / 动作卡片）
gradlew.bat :app:kspDebugKotlin      # 只跑 Room 注解处理，导出 app/schemas/.../7.json
```

**关于证书 / 代理**：仓库里的 `gradle.properties` **只放通用配置**，不含任何机器专有的
证书路径或口令。如果你的网络环境有 HTTPS 拦截（需要自定义信任库），不要改这个文件，
用命令行 `-Dorg.gradle.jvmargs=...` 覆盖，或写进本机的 `~/.gradle/gradle.properties`。

## 四、使用方法

### 第一次使用

1. 打开「**我的**」→ 填身高 / 体重 / 年龄 / 性别（体脂率可不填）→ 选活动系数与
   目标模式，下方立刻显示 BMR / TDEE / 目标热量与建议的碳水、蛋白质、脂肪克数；
2. 回到「**今日**」开始记录。

### 每天怎么用

- **记饮食**：今日页「今日饮食」右上角「+」→ 选食物 → 按克数或按份数填量 → 保存。
  顶部三条进度条会实时变色。
- **记运动**：今日页「今日运动」右上角「+」→ 选一项（跑步、游泳、撸铁…）→
  填时长，热量自动算出来；想按实际手表数据填就点编辑直接改热量。
- **记撸铁**：选「撸铁」→ 给它填个时长（它本身也消耗热量）→ 点「加动作」→
  从动作库选一个 → 点动作卡片，用**三个滑轮**选重量 / 组数 / 次数。
- **建自己的动作**：库 → 运动 → 撸铁 → 右上角「新建动作」。
- **看某一天**：顶部日期栏左右切换，或点中间选日期，能看到那天吃了什么、练了什么。

### 几个行为约定

- 运动消耗**不会**加回可摄入额度，只做显示参考；
- 撸铁是一个普通运动项目，**同样按 MET 算消耗**，同时可以挂动作卡片；
- 动作卡片是**单一值**：`动作名 + 重量 + 组数 + 次数`，不做「每组次数不一样」；
- 重量滑轮按 **2.5kg** 递增，组数 1-20，次数 1-100。

## 五、输入输出示例

### 例 1：身体数据 → 每日目标

| 输入 | 值 |
|---|---|
| 身高 | 175 cm |
| 体重 | 70 kg |
| 年龄 | 25 |
| 性别 | 男 |
| 体脂率 | 不填 |
| 活动系数 | 中度 ×1.55 |
| 目标模式 | 保持 |

**输出**

```
基础代谢 BMR（Mifflin）  1674 kcal
每日总消耗 TDEE（参考）   2594 kcal
目标热量                 1995 kcal
建议每日目标：碳水 245 g / 蛋白质 112 g / 脂肪 63 g
```

（碳蛋脂都按体重算：70kg × 3.5 / 1.6 / 0.9 = 245 / 112 / 63 g；
目标热量 = 245×4 + 112×4 + 63×9 = 1995 kcal。注意**不是** TDEE × 倍率。）

若体脂率填 18.5%，会额外显示一行「BMR（Katch-McArdle 参考）」，但 TDEE 仍按上面算。

### 例 2：食物 → 营养与热量

输入：食物选「大米」，重量 100 g（该食物数据为每 100g）

输出（记入当天摄入）：

```
碳水 79 g · 蛋白质 7.5 g · 脂肪 0.5 g · 约 351 kcal
```

热量由碳蛋脂按 4/4/9 反算：`79×4 + 7.5×4 + 0.5×9 = 350.5 kcal`。

### 例 3：运动 → 消耗热量（MET）

| 输入 | 值 |
|---|---|
| 运动 | 慢跑（MET 6.0） |
| 时长 | 90 分钟 |
| 体重 | 70 kg（取自身体数据） |

**输出**：`6.0 × 70 × 1.5 = 630 kcal`

跑步（MET 8.3）跑 30 分钟则是 `8.3 × 70 × 0.5 = 290.5 kcal`。这些数字都可以手改。

### 例 4：撸铁 → 动作卡片

| 输入 | 值 |
|---|---|
| 运动 | 撸铁（MET 6.0） |
| 时长 | 60 分钟 |
| 动作 | 杠铃卧推 |
| 重量 / 组数 / 次数 | 60 kg / 4 组 / 8 次 |

**输出**

```
撸铁   60 分钟 · 420 kcal
  └ 杠铃卧推   60kg × 4 组 × 8 次    （总容量 1920 kg）
```

下次再添加杠铃卧推时，重量 / 组数 / 次数会**自动预填上次的值**。

### 例 5：一天的账

```
饮食摄入  1984 kcal
运动消耗   770 kcal   （慢跑 90 分钟 630 + 撸铁 20 分钟 140）
总热量     1214 kcal
```

「总热量」= 摄入 − 消耗。注意**可摄入额度不会因为运动而增加**。

## 六、项目结构

```
app/src/main/java/com/example/diettracker/
├── data/
│   ├── db/            Room 实体 / DAO / 数据库
│   │                  ActivityLogEntity = 当天一项运动（运动 + 时长 + MET 热量）
│   │                  ExerciseLogEntity = 撸铁下的动作卡片（重量 + 组数 + 次数）
│   ├── model/         枚举与领域常量（目标模式、活动系数、宏量营养素…）
│   ├── repository/    DietRepository（饮食）、ActivityRepository（运动与身体数据）
│   └── seed/          内置食物：麦当劳 / 品牌食品 / 推荐食品 / 常见食物 / 包装食品
├── domain/            纯逻辑：营养计算、运动库（33 项 + MET）、动作库、拉伸库
├── ui/
│   ├── screens/       今日 / 库（运动·撸铁·拉伸·食物）/ 我的 / 目标 / 食物编辑…
│   ├── viewmodel/     ViewModel + StateFlow
│   ├── components/    进度条、滑轮选择器、运动卡片、拉伸卡片、日期导航…
│   └── navigation/    路由与底部栏
└── util/              日期与数字解析

app/src/test/…/SportRulesTest.kt   运动规则单元测试（17 项）
app/schemas/…/7.json               Room 导出的库结构
apk/                               构建好的 APK（不入库，发布走 Releases）
```

**关于数据库版本**：v6 → v7 把「训练日 + 频率 + 步进」整套模型换成了
「运动项目 + 时长 + MET」，旧表语义上无法映射，因此那是**唯一一次**允许丢数据的
升级。**从 v8 起改为真正的迁移**，每个版本配一个 `Migration`，升级不会清空数据：

```
v7 → v8   新增 day_notes / personal_records / custom_sports 三张表（纯新增，无损）
v8 → v9   新增 seed_versions 表，用于内置数据的增量更新
```

**内置数据的增量更新**：食物库等内置内容会随版本增加条目。每批数据在
`seed_versions` 表里记一个版本号，启动时只补**版本落后**的批次，并且只插入库里
不存在的名字——所以你自己改过、删过的条目不会被覆盖，也不会被塞回来。

给内置数据加条目时只需要两步：把条目加进对应的 `*Foods.kt`，再把
`SeedVersionEntity` 里那一批的版本号 +1。

**改动迁移后请跑一次校验**（比对迁移 DDL 与 Room 导出的 schema 是否逐字符一致；
不一致会在真机上抛 `Migration didn't properly handle ...`）：

```bash
python tools/verify_migrations.py
```

## 七、已知限制

1. **热量是碳蛋脂反算的**（4/4/9），食物表没有单独的「官方热量」列。少数条目反算值
   和来源对不上，备注里写了来源热量：牛油蛋糕（来源 420 / 反算 536）、芝士蛋糕
   （320 / 376）、出前一丁大盛杯面（445 / 缺碳水）、子母朱古力与 DHA+（70、57 / 缺蛋白）、
   青岛·雪花·哈尔滨啤酒（42、43、34 / 酒精热量不在碳蛋脂里）。
2. **饮料按每 100ml 录入**并写在备注里（应用内部按每 100g 存）；星巴克因为官方只给
   「每份 Grande 473ml」，走按份计量存原始值、不做换算。
3. **完全离线**：没有账号、没有云同步；换手机需要自己迁移数据。
4. **拍照识别食物、AI 导入尚未实现**（方案已定：本地离线 OCR + 手动确认，不会让模型
   编造营养值）。
5. 内置数据里标注为「第三方 / 估算」的条目仅供参考，请以包装标示为准。
6. 运动消耗是 MET 估算值，个体差异很大（强度、效率、动作标准度都会影响），
   建议按自己的实际数据手动修正。
